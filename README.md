# EpiGuard · эпидемиологическая система для Таджикистана

Работающий локальный проект на **Python / Django**, с JavaScript без внешних CDN, адаптивным интерфейсом, базой данных, разграничением доступа и автоматическими тестами. Создан по приложенному контексту от 17 октября 2026 года и перечню заболеваний заказчика.

**Текущий статус: функциональная демонстрационная версия для проверки процессов.** Реальные пациенты, внешние реестры и официальные каналы СЭС не подключены. «Работает локально» не означает готовности к эксплуатации с медицинскими данными.

## Открыть сейчас

- Адрес: **http://127.0.0.1:8017/**
- Для повторного запуска: дважды щёлкните **`START.bat`**. Оставьте открытым окно сервера.
- Или PowerShell: `./start.ps1` (если локальная политика допускает запуск скриптов).
- Остановить сервер: `Ctrl+C` в его окне.
- Пароли сгенерированы случайно и записаны **только в локальном файле `.demo-credentials.txt`**. Они не зашиты в исходники и не выводятся на странице входа.

| Логин | Назначение |
|---|---|
| `epi.demo` | Основной демонстрационный эпидемиолог; все настроенные учебные СЭС |
| `doctor.demo` | Медработник; только лично созданные случаи |
| `lab.demo` | Лабораторный сотрудник; только свои случаи, без произвольного поиска чужих пациентов |
| `district.demo` | Эпидемиолог только учебной СЭС Сино |
| `admin.demo` | Суперпользователь; настройка справочников, пользователей и доступов |

Справочник содержит **48 записей и 5 групп отчёта**, включая весь предоставленный перечень, малярию, холеру, чуму, бешенство и дополнительные позиции из контекста. В демонстрации 54 вымышленных случая с разными статусами. Учреждения и маршруты с префиксом «ДЕМО» — учебные, не официальная структура СЭС.

## Что уже работает

- Вход по паролю, подтверждение допуска администратором, блокировка частых неудачных попыток, TOTP с защитой от повторного использования кода. В рабочей конфигурации MFA обязательна.
- Постоянный медицинский ID пациента, отдельный UUID случая, отдельные извещения для получателей. Выбор существующего пациента ограничен доступными записями.
- Черновик → отправка → принятие ведущей СЭС → расследование → завершение; повторное открытие с основанием.
- Проектный эпидномер `EP-ГОД-последовательность` при принятии. Номер сохраняется при передаче и отмене, повторно не выдаётся. Последовательность общая и не сбрасывается ежегодно.
- Ручная настройка маршрутов по территории, несколько получателей одного случая, просмотр и принятие внутреннего извещения. Если маршрута нет, случай остаётся ненаправленным для назначения суперпользователем.
- Передача другой СЭС с принятием / возвратом и сохранением ответственности отправителя до принятия.
- Отмена с обязательной причиной. Ручная отметка дубля того же пациента и инфекции; исходные записи и источники сохраняются.
- Версии индивидуальных анкет, снимок вопросов в случае, условные вопросы. Использованная версия не редактируется обычным способом; нужно создать новую.
- Общий и индивидуальный эпиданамнез, разные адреса, исторические сведения о поликлинике, образовании и возрасте.
- Очаги, связанные случаи, контакты, мероприятия и их исполнение, лабораторные исследования. Исправление результата — новая запись со ссылкой на старую, без автоматического изменения диагноза.
- Сигналы и их проверка отдельно от статистики инфекционных случаев.
- Поиск, фильтры, постраничные списки, обзор и график по дате выявления.
- Отчёт по периоду, дате учёта, заболеванию / группе, территории, полу, диагнозу и возрасту; строки по заболеваниям, территориям, адресам, поликлиникам, школам / детсадам.
- Непересекающиеся возрастные группы и отдельный итог 0–17; раздельное число школьников и уникальных школ, детей в детсадах и уникальных детсадов.
- Excel с условиями отбора и защитой текстовых ячеек от формул; печать / сохранение в PDF через браузер. Сохранённые шаблоны условий отчёта.
- Схема центров территорий с количеством случаев и явным счётчиком записей без геопривязки. Это не карта официальных административных границ.
- Закрытые документы PDF / PNG / JPEG; скачивание только через проверку доступа. Размер и сигнатура файла проверяются.
- Журнал просмотров, выгрузок и изменений с прежними / новыми значениями. Обновление и удаление журнала запрещены прикладным API.
- Защита от перезаписи устаревшей версии случая; повтор отправки формы создания с тем же ключом не создаёт новый случай.
- RU / TJ / EN для навигации, основных полей, статусов и названий заболеваний. Разъяснения, часть второстепенных подписей, ошибки и часть вариантов анкет пока на русском; полный профессиональный перевод требует проверки.
- Команды локальной резервной копии и проверки целостности без перезаписи рабочей базы.

## Установка с нуля

Python 3.12–3.14; проверено на установленном Python 3.14.6. Используется Django 6.0.9. Поддержка Python описана в [официальной документации Django 6.0](https://docs.djangoproject.com/en/6.0/releases/6.0/).

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8017 --noreload
```

Команда `seed_demo` идемпотентна: повторный запуск не меняет пароли и не дублирует демозаписи. Не запускайте её для реальных данных. Для чистой среды используйте `seed_demo --catalog-only`, новый PostgreSQL и `createsuperuser`. Не переносите демонстрационную базу в рабочую.

## Проверка

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
node --check static\js\app.js
```

Тесты охватывают права доступа, прямые ссылки и документы, маршрутизацию, передачу / возврат, отмену, дубли, идемпотентность создания, конфликты, возрастные границы, исторические снимки, школы, контакты, исправления лаборатории, анкеты, CSRF, блокировку входа, TOTP, переводы и Excel. Используется отдельная тестовая БД.

## Структура

```text
config/                        настройки, URL, WSGI
surveillance/models.py         основные сущности
surveillance/access.py         единая область доступа
surveillance/services.py       атомарные переходы и версия случая
surveillance/forms.py          серверные проверки
surveillance/reporting.py      фильтры и возрастная агрегация
surveillance/views.py          рабочие экраны и защищённые документы
surveillance/catalog.py        болезни, группы, проектные анкеты
surveillance/tests.py          автоматические проверки
templates/                     серверные HTML-шаблоны
static/css/, static/js/         локальные стили и JavaScript
docs/                          требования, решения и эксплуатация
```
