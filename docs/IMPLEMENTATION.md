# Реализация и принятые проектные решения

Дата: 17 октября 2026 года. Основание: приложенный контекст, а не утверждённый нормативный акт.

## Сопоставление требований

| Раздел контекста | Текущая реализация / граница |
|---|---|
| Пациент / случай / извещение | Раздельные таблицы Patient, Case, Notification. Каждое исходное сообщение пока представлено своим случаем; ручная связь duplicate_of сохраняет источники, но полноценная отдельная таблица входящих сообщений ещё нужна. |
| Заболевания | 48 кодов; все позиции заказчика сохранены в справочнике либо в итоговых группах. Терминологические неоднозначности помечены. |
| Анкеты | Общие проектные вопросы для каждой болезни; отдельные вопросы для кори, малярии, бруцеллёза, сибирской язвы. Полные официальные индивидуальные анкеты не предоставлены и не изобретались. JSON-схема поддерживает условные вопросы, версии и утверждение. |
| Эпидномер | Явный временный порядок: выдача при принятии ведущим эпидемиологом. В интерфейсе обозначен как проектный. Изменение официальной схемы требует отдельной миграции / сервиса, не перенумерации старых записей. |
| Отмена / дубли | Причина обязательна, запись и номер сохраняются. Дубли отмечает эпидемиолог; только для того же медицинского ID и диагноза. Это защита от ошибочного объединения, а не окончательные критерии эпизода. |
| Статусы | Диагноз и рабочий процесс разделены. Подтверждение требует даты; наличие положительного теста само по себе не меняет диагноз. |
| Маршруты | Явные Route для территории: один ведущий получатель и несколько информируемых. Автоматического предположения о трёх уровнях нет. Без маршрута — ручное назначение суперпользователем. |
| Передача | До принятия отвечает отправитель. При возврате остаётся прежняя СЭС. Все действия фиксируются; эпидномер неизменен. Получатели прежних уведомлений сохраняют чтение; редактирование — только ведущей службе. |
| Очаги | Установление, случаи, источник, территория, ответственная СЭС, завершение с причиной. Развёрнутый редактор связей, закрытие по согласованным критериям и версия карточки очага — следующий этап. |
| Контакты | Запись к случаю, место, сроки наблюдения, статус, связь с заболеванием. Уникальность по Patient / identity_key. При отсутствии медицинского ID разные записи не объединяются по ФИО. Редактор наблюдения сохраняет основание и историю. Повторный контакт можно явно связать с ранее добавленным человеком без медицинского ID; ключ объединяется по решению эпидемиолога. |
| Мероприятия | Вид, объект / основание, ответственный, срок, результат. Ограничения требуют документа. Самостоятельный учёт штрафов, продлений карантина и решений органов не реализован. |
| Вакцинация | Исторический статус, источник и причина отсутствия. Задача вакцинации не считается дозой. Обмен с общей медкартой, прививочным модулем, сериями вакцин и НППИ не подключён. |
| Лаборатория | Несколько проб, результаты, ссылки исправления. Старый ответ не удаляется; лабораторное изменение не превращает подозрение автоматически в подтверждение. Разрешение лаборатории работать с чужим случаем пока не предоставлено. |
| Доступ | Медработник — свои случаи; эпидемиолог — уведомлённые / ответственные службы и свои черновики. Изменения — ведущая СЭС либо автор до принятия. Администратор пользователей без клинической роли не видит реестр. Суперпользователь имеет отдельный явный полный доступ. Делегирование / замещение с датами не реализовано. |
| Аудит | Журнал внутри БД, старые / новые поля, просмотры / выгрузки. Приложение не удаляет журнал. Это не защита от владельца БД или ОС; внешнее неизменяемое хранилище / SIEM не подключено. |
| Отчёты | Указанные фильтры и строки, непересекающиеся возраста, отдельные образовательные показатели, сохранённые условия, Excel и браузерная печать PDF. Замороженные версии сданных отчётов, произвольный конструктор столбцов, официальные бланки, несколько диагнозов произвольным набором, население / знаменатели — следующий этап. |
| Карта | Центры территорий, схема, количество и отсутствие геопривязки. Проверенные полигоны, геокодирование, картографическая подложка и официальные границы отсутствуют. Близкие точки разнесены с соединительными линиями. |
| Задачи | Виджеты ненаправленных извещений, непросмотренных уведомлений, просроченных мероприятий и неизвестного возраста. Нулевая отчётность, учреждения не отчитались и автоматическая эскалация сроков не реализованы. |
| Языки | Основные формы и навигация, статусы, заболевания на RU / TJ / EN. Остальные пояснения и часть анкет требуют перевода и профессиональной вычитки. |
| Сигналы / One Health | Сигналы отдельно от случаев, связь с очагом. Ветеринарные обстоятельства можно записывать в проектной анкете. Реальных ветеринарных / экологических интеграций и автоматических порогов нет. |
| Надёжность | Транзакции, уникальные ограничения, версия случая, ключ повтора создания, индексированные списки. Очередь внешней доставки с повтором, полноценный offline, импорт старых журналов и горизонтальное масштабирование не реализованы. |

## Правила статистики в этой версии

1. По умолчанию не считаются черновики, отменённые случаи, исключённые диагнозы и помеченные дубли. Подозрение и вероятный диагноз входят в сводку по выбранным условиям; это видно через фильтр диагноза. Принятие СЭС не равно клиническому подтверждению.
2. У каждого случая один основной код. Итоговые строки «Ҳамагӣ бемориҳои сироятӣ», «Ҳамагӣ БШРМ», «Гепатитҳои вирусӣ», «Бемориҳои паразитарӣ» — группы, а не диагнозы. Фильтр группы выбирает случаи один раз.
3. «Сил», «Сили шуш» и «Сил (БК+)» временно доступны раздельно. Аналогично ВИЧ и СПИД, носительство и гепатит. Для одного эпизода не создавайте отдельные случаи по каждому пересекающемуся названию. Автоматическое сопоставление и официальные правила необходимо согласовать.
4. Возраст хранится в снимке на дату начала симптомов, иначе на дату выявления. При неизвестной дате рождения можно указать приблизительный возраст. Это временное правило; исходный документ предлагал запасную дату регистрации, но до принятия она отсутствует. При переходе к официальному правилу понадобится миграция с явной версией расчёта.
5. Текущая правка дат случая пересчитывает возраст в этой записи с аудитом. Изменение основной карточки пациента само по себе не меняет исторические поля. Сданные отчёты пока не фиксируются как неизменяемые версии.
6. Без выбранного периода записи с неизвестной датой остаются в общей сводке. При выбранном периоде их нельзя отнести к нему; количество таких записей до ограничения периодом показано отдельно.
7. Число уникальных школ / детсадов определяется по точному тексту исторического наименования. До загрузки официального справочника различное написание одного учреждения может увеличить число учреждений.
8. Количество контактных — уникальные связанные медицинские ID или ключи контакта. Без идентификации точная дедупликация между учреждениями не гарантируется.
9. Число на 100 000, лабораторная доля положительных, «нет случаев» при отсутствии нулевого отчёта и автоматические медицинские критерии не вычисляются.

## Необратимые действия и доступ

Обычного удаления медицинских записей нет. Смена состояния выполняется POST с CSRF и серверной проверкой. Исправление случая и значимые переходы требуют основания. Предыдущие уведомлённые службы сохраняют чтение в рамках текущей модели; иной порядок архивного доступа необходимо отдельно утвердить.

Модель Role «администратор пользователей» сама по себе не даёт доступа к Django admin. В этом прототипе конфигурацию меняет суперпользователь. Полноценное отдельное безопасное управление пользователями без клинического доступа, несколько согласующих и временное замещение ещё следует разработать.

Нет рассылки email, SMS, Slack или сообщений в реальные учреждения. Внутреннее извещение является строкой получателя в той же транзакционной БД. Не следует называть его подтверждением внешней доставки.
