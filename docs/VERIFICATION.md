# Проверка 17 октября 2026 года

Окружение: Windows, Python 3.14.6, Django 6.0.9, SQLite, локальный адрес 127.0.0.1:8017.

- `manage.py check`: без замечаний.
- `manage.py test`: **36 тестов пройдено** в отдельной тестовой БД.
- `manage.py makemigrations --check --dry-run`: незаписанных изменений схемы нет.
- `node --check static/js/app.js`: синтаксических ошибок нет.
- `manage.py check --deploy` с отдельными временными переменными `DEBUG=0`, `DEMO_MODE=0`, MFA, секретом и разрешённым hostname: без замечаний. Это проверка конфигурации, не развертывание.
- Резервная SQLite-копия создана через backup API; `verify_backup` проверяет SHA-256, `integrity_check` и открывает таблицу случаев. Рабочая база не перезаписывалась.
- Браузер: вход демонстрационного эпидемиолога, обзор, адаптивный экран и широкий экран, динамическая загрузка индивидуальной анкеты малярии. При проверке загрузки анкеты ошибок JavaScript не обнаружено.
- Обнаруженная при проверке проблема формата начальной даты исправлена: HTML date получает ISO `YYYY-MM-DD`. Новый пациент по умолчанию имеет неизвестный пол, а не первый вариант списка.

Автоматические тесты проверяют:

1. Один случай с тремя внутренними уведомлениями и номером при принятии.
2. Отмену с обязательным основанием, сохранением номера и правильным исключением из статистики.
3. Недоступность чужого случая в списках, прямых ссылках, действиях и документах.
4. Запрет медработнику принимать / передавать случай.
5. Отсутствие произвольного назначения при ненастроенном маршруте.
6. Принятие и возврат передачи с сохранением ответственности и номера.
7. Конфликт устаревшей версии перехода / исправления и сохранение пользовательского ввода.
8. Дубли, один счётчик в отчёте и сохранённые исходные записи.
9. Возрастные границы, отдельный итог 0–17 и исторические снимки.
10. Повтор сохранения формы с тем же ключом без создания второго случая.
11. Выбор существующего пациента без перезаписи его личности.
12. Сохранение версии анкеты и условные ответы.
13. Отбор по датам, территории и статусам, число школьников отдельно от числа школ.
14. Уникальность контактов по пациенту и явной связи прежнего контакта; наблюдение с историей и защитой от конфликта.
15. Исключение сигналов из числа случаев.
16. Исправление лабораторного результата без удаления старого и без автоматической смены диагноза.
17. Сигнатуры документов и ограниченное скачивание.
18. Отсутствие клинического доступа у администратора пользователей.
19. Запрет прикладного изменения / удаления аудита, CSRF и ограничения входа.
20. Контроль допуска, TOTP по RFC-вектору и защита от повторного кода.
21. Стабильность итогов при смене языка и защита Excel от формул во входном тексте.
22. Отрисовку основных экранов в разрешённой области доступа.

PostgreSQL, внешний HTTPS-прокси, боевой сервер, реальная интеграция СЭС, восстановление отдельного сервера и нагрузка не проверялись: соответствующая инфраструктура не предоставлена. Официальные медицинские критерии и перевод не утверждались.
